# Taste
- Finds plain, default-looking UI "boring" — expects visual overhauls to be comprehensive and bold (color palette, typography, spacing, overall polish), not just small tweaks. Their vibrancy bar keeps escalating: even after a bold multi-hue pass they said "this looks minimal still" and asked for MORE hues (purple/blue on top of an already-vivid palette), explicitly wanting it "flashy and attention gathering" and "very high tier — something someone with 20 years exp in UI UX design and front end makes" — heavy saturated color, but always applied "tastefully" (hues join rotations/tints and small pops, never flood surfaces). Confidence: 0.85
- Strongly dislikes beige/off-white/light backgrounds; wants dark, flashy stages. Explicitly rejected the beige "paper" background ("I am generally not liking the background at all") and had the whole site flipped to a deep indigo-black theme with aurora glow meshes, film grain, glass panels, and neon accent hues. Also dislikes fussy background textures like grid lines ("this checkboxes on the background looks bad"). Confidence: 0.9
- Wants Apple-style BI-DIRECTIONAL scroll animations in web UI: elements animate in (blur + lift) as they enter scrolling down AND dissolve/re-hide when scrolled out going up — re-triggering on every pass, nothing stays static after first reveal. Implement via a shared Reveal primitive (IntersectionObserver toggling on isIntersecting in both directions) so one file upgrade applies to every surface at once. Confidence: 0.85
- For large multi-file tasks, explicitly asks to fan out work to multiple parallel sub-agents to finish faster; values speed and is comfortable with the agent orchestrating concurrent agents — user frames this as their standing habit ("as usual, spawn multiple agents to do it quicker") and escalates the count when in a hurry ("spawn not 5 but 10 agents and finish is very quickly"). Confidence: 0.9

Confidence: 0.75
- Grants broad command access and expects autonomous setup — e.g., installing missing tooling globally (npm -g) to complete verification without asking first. Confidence: 0.6
- On interrupted multi-agent runs, resumes autonomously from a terse go-ahead ("no continue") instead of asking questions: first verify on disk what actually landed (grep for characteristic markers of the change), then relaunch agents only for untouched files, telling them those files are untouched and they are the sole agent on them. Confidence: 0.65

- Before declaring UI work "done", verifies the result: production build passes plus screenshots of the running dev server (agent-browser) at several scroll positions and routes, reviews them, then closes the test browser session. Confidence: 0.6
